# Corum-Ranked repository instructions

## Deployment policy (authoritative)

- `main` is the authoritative source for the Corum Ranked server and mod.
- Standing user authorization: unless a later request explicitly limits a stage, finish every patch with a normal main push, Debug R2 publication, and Singapore production server activation in the same task.
- Pre-launch pipeline (user instruction 2026-11-02): Release builds and Debug-OFF validation are paused. `ranked-release.yml` runs validate -> Debug build -> Debug R2 publication -> Lightsail production. Supported build platforms for now: Windows, iOS, Android32 and Android64 (macOS paused). Workflows run on main pushes or manual dispatch only; branch and PR pushes run nothing. `build-ranked-mod.yml` (Release) stays manual-only. Server admission advances when the Debug package is public (`RANKED_ROLLOUT_CHANNELS`); restore `release` there and in `verify-published-clients.py` when Release publication returns. Preserve concurrent user changes. Verify the new immutable client packages before activating their required version; carry out the existing gated workflows without asking for deployment permission again, and report any external execution blocker accurately.
- For Singapore deploys use verified GitHub environment lightsail-production variable `LIGHTSAIL_HOST=52.74.37.130` and verified `LIGHTSAIL_SSH_KNOWN_HOSTS`; keep `StrictHostKeyChecking` enabled.
- Deploy to Lightsail using manual `deploy` or an explicit main commit marker `[deploy-lightsail]`; ordinary pushes deploy only if `LIGHTSAIL_AUTO_DEPLOY=true`. A `[no-deploy]` push is always skipped, including when auto-deploy is enabled; manual `deploy` is still available. Keep a single authoritative Neon writer, and verify live `/health` and `/ready`.
- A `[build only]` marker controls only optional R2 publishing in the Ranked mod workflows and does not control Lightsail deployment. Keep build-only and R2 release decisions separate from the server deploy decision.
- After changing the client version, verify the Lightsail deploy, the Debug R2 package publication, client mod updates and the live Singapore API. Never treat a green build as proof of completed publication or physical-device behavior.
- `ranked-release.yml` coordinates main releases: reusable `ranked-ci.yml`, `build-ranked-debug.yml` and image preparation run in parallel; Debug publication requires validation and the complete Debug build, and Singapore activation requires the Debug channel and the same source SHA. Manual full/check-only paths remain available. Verify their actual run status; a workflow run being created does not imply its jobs executed or succeeded. Investigate zero-step/zero-runner-time failures at the GitHub Actions account/runner level.
- Immutable Cloudflare R2 package publication is a separate release stage, gated by `RANKED_PUBLISH_R2` and successful package builds. Do not bypass this protection or expose R2 credentials solely to force publishing.
- Version changes must synchronize `corum-ranked-mod/mod.json`, Ranked workspace package metadata/lockfile, and `ranked/apps/server/src/session/client-version.ts`.
- Do not describe an untested iOS/Android native change as verified. Server deploy success does not mean a compatible packaged client was published.
- Sole supported hosting target: AWS Lightsail Singapore `https://api.52-74-37-130.sslip.io`, with Neon Singapore as its single authoritative writer. Railway and Render support, deployment targets, update bridges and client fallback URLs are retired by the user's 2026-10-25 instruction. Preserve historical rollout records as history; do not restore those platforms or deploy retired Seoul.

- The release coordinator builds the Lightsail image concurrently with Release/Debug and uses explicit publication dependencies. The activation barrier re-downloads each rollout channel (currently Debug: full bytes/hash, embedded identity/version/channel/source SHA, every supported platform binary), without 40-minute polling. Missing/corrupt/mixed-SHA packages fail closed. Activation rechecks current main after image upload; never cancel an active rollback-capable SSH deployment. No second activation push is required for a `[deploy-lightsail] [publish-r2]` source push.
- If release upload steps fail with "Artifact storage quota has been hit", run the manual `cleanup-artifacts.yml` workflow (deletes every stored artifact; packages live in R2), then re-run the release on current main.
