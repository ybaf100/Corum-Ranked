## Supplied device evidence and causes

The three October 18 Geode logs identify iOS, GD 2.2081, Geode 5.11.2 and Corum Ranked beta.76 Debug. The first run loads both Level Thumbnails 2.6.1 and ImagePlus 1.1.1, repeatedly opens Pause and reaches the native paused state, but records no Survival surrender/Force Clear confirmation callback and no successful thumbnail response. The third run has ImagePlus disabled and Level Thumbnails disabled by its unresolved dependency, so numeric fallback is expected there. These logs contain no crash backtrace beyond normal crash-handler initialization.

Thumbnail responses were discarded before decode: Geode's header map preserves wire spelling and uses a case-sensitive lookup, while this API returns lowercase HTTP/2 `content-type` and `location`. The provider asked for `Content-Type` and `Location`. The live small-image response and random redirect reproduce those lowercase names. Selection could also start empty thumbnail cards before previews existed and reconsider its mode after a context/scene change.

Pause's fallback menu lookup passed the Pause itself to `getChildBySpriteFrameName`, which only searches direct children. The resume item is inside its native `CCMenu`, so this path missed it before Node IDs assigned names. Separately, menu priority adjustment alone does not guarantee delivery of a Begin/End pair when native Pause/UI swallowing delegates register or change priority after custom setup. The supplied logs do not expose the exact iPad handler priority. A public-Cocos dispatcher harness reproduces the swallowed Begin with visible, enabled items; the new observer is tested against that condition instead of invoking callbacks directly.

## Implementation

- `RankedPauseLayer.cpp` finds the native menu through its actual child menus. New `ui/SurvivalPauseActionInput.{hpp,cpp}` belongs to the exact Pause, PlayLayer and scene. It takes only enabled Survival action rectangles, using the item's transformed node coordinates. It aligns its own handler ahead of the owned native blockers after registration and checks again each frame. It does not rewrite unrelated handlers or force-enable buttons. All visible native/Geode dialogs suppress it. Permission/handler/Begin diagnostics distinguish later policy or device-input failures.
- Touch cancellation, movement outside the item, a second finger, pending actions, detached owners, scene replacement and retirement suppress callbacks. Invocation uses `queueInMainThread` and WeakRefs. The existing own confirmation, server permission checks, duplicate-event protection, ACK-gated surrender/Force Clear, and exact-owner deferred quit remain authoritative. Resume/quit suspends the observer before Pause cleanup. Release builds bind no Force Clear action; online and Death Match Force Clear policy is unchanged. No `levelComplete()`, vanilla reward/save or global touch reset was added.
- `SurvivalThumbnailProvider.cpp` compares header names case-insensitively and retrieves values with their original name. Same-origin redirects, optional loaded-mod checks, request/byte/dimension limits, generation cancellation, negative/disk/GPU caches and CPU-decode/main-thread-upload boundaries remain in place. The existing roster time warms previews even before a server level ID exists. A confirmed reveal picks a mode once; numeric fallback stays selected for that round across late image arrivals and coordinator recreation. Pending selection shows a neutral status if no preview exists.
- Server rules expose `entryOpensAt = entryRequestedAt + 3000`. An early `ENTERED` is rejected until that deadline. The online absence adapter and bot entry timing use the same derived deadline. No database migration is needed. The existing native gameplay countdown and 180-second round timer remain separate.

The selection header/readiness row shows a translated all-ready countdown. Waiting-room surrender stays available, including during these three seconds, and the server still settles it on ACK.
- `SurvivalSelectedMapPanel`, `SurvivalOptionSwitch` and `SurvivalSelectionLayout` retain the LDM menu item as disabled `NO LDM` / `LDM 없음` for unsupported maps. Its position and the Shake/Jukebox/READY positions stay fixed. Saved global defaults and same-round overrides are preserved. Korean glyphs are already present in every active font weight. The layout preview tool reflects the visible disabled control.
