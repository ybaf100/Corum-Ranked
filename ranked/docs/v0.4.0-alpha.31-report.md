# Corum Ranked v0.4.0-alpha.31 report

## Scope

LAST ATTEMPT spectator presentation and Debug Bot `ROUND_SETTLING` continuation fix. The 10-second LAST ATTEMPT start deadline and normal PvP attempt semantics are unchanged.

## Root causes

1. The server/client runtime already marked the two-Clear trigger player as `spectatorActive` during `LAST_ATTEMPT_WINDOW`, but `RankedPopup::renderMatch` only rendered the spectator screen in `ROUND_SETTLING`. For the first 10 seconds it incorrectly reused the normal prepare screen and displayed `STARTS IN ...`.
2. `DebugBotService` only drove Bot attempts in `ROUND_PLAYING`, `FINAL_ATTEMPT_WINDOW`, and `LAST_ATTEMPT_WINDOW`. If an accepted Bot attempt remained alive when the start window expired, `MatchService` correctly moved the round to `ROUND_SETTLING`, but the Bot simulator stopped ticking and never sent the matching Attempt End.

## Fix

- Render the spectator wait screen immediately for `LAST_ATTEMPT_WINDOW` whenever `spectatorActive=true`.
- Show `WAITING TO START` plus remaining start-window time until the opponent actually has an active attempt; switch to live progress once it starts.
- Continue an already-started Debug Bot attempt through `ROUND_SETTLING`. New starts remain forbidden in that state.
- Recover an open authoritative Bot attempt from PostgreSQL if the debug driver is rebuilt during `ROUND_SETTLING`.
- Extend the Debug Bot integration regression test past the 10-second boundary and assert that no open Bot attempt remains.
