# Corum Ranked v0.5.0-beta.3 report

## Supplied-log diagnosis

The supplied client reached authoritative `ROUND_PLAYING` and armed the selected level, so queueing, Ready, map download, and server authorization were not the primary failure. beta.2 pulsed the visible item but dispatched gameplay through an unattached selector proxy; its callback ran without Geometry Dash leaving `LevelInfoLayer`, producing the repeated `STARTING` watchdog loop.

## Client launch fix

- Resolves the real Play item from the live vanilla menu and normalizes that item's target to the active Ranked `LevelInfoLayer`.
- Calls the real item's `activate()` and forwards through vanilla `LevelInfoLayer::onPlay`; no Ranked code constructs, pushes, replaces, or switches directly to a `PlayLayer` scene.
- Keeps every non-song control disabled during waiting and removes the manual Play fallback entirely.
- Automatically retries the real button while the selected map and authoritative start window remain valid.
- Clears the LevelInfo UI launch latch after a successful vanilla transition, allowing `PlayLayer::onQuit` to return to the same map page and automatically start the next legal attempt.
- Re-entry is still denied by `RankedRuntime::canEnterCurrentLevel()` after timeout, spectator/result/settling state, optimistic three-clear completion, Deathmatch attempt exhaustion, or map/context replacement.

## Operational fixes

- `Ranked Tiers.Main Pool` now drives candidate selection. Main Pool 1 uses 2/2/1 from Pools 1/2/3; Main Pool 2..5 uses 1/3/1 from previous/main/next; Main Pool 6 uses 1/2/2 from Pools 4/5/6.
- Default RED/AQUA/BRONZE/SILVER/GOLD rows retain their former distributions.
- CSMP tier names are now operator-defined and independent from fixed Ranked display tiers. English and Korean names are normalized and accepted.
- Apps Script fails closed for missing `NONE`, missing/non-finite Seed MMR, duplicate CSMP names, and a `CSMP Tiers` row without a matching Seed row.
- Migration `0006_v050_dynamic_csmp_tiers.sql` replaces the fixed DB whitelist with a normalized 1..80-character constraint. Existing profiles remain one-time seeded and are not automatically re-seeded.

3. Deploy the beta.3 server and confirm `/ready` is healthy.
4. Build and distribute the exact `v0.5.0-beta.3` Geode client.
5. On a real device, confirm the log records `Activating real Ranked Play button`, followed by `Ranked LevelInfo onPlay forwarded to vanilla` and `Ranked PlayLayer initialized through vanilla Play`.
