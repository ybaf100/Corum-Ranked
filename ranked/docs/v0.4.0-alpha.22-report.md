# Corum Ranked v0.4.0-alpha.22

## Resource prepare / song input

Preparation remains on the real Geometry Dash `LevelInfoLayer`. The alpha.21 gate disabled entire `CCMenu` touch dispatch trees, which could leave `CustomSongWidget::m_downloadBtn` visible but inert. Alpha.22 keeps menu dispatch alive, disables individual non-song `CCMenuItem`s, and explicitly leaves the vanilla song acquisition controls (`m_downloadBtn`, `m_cancelDownloadBtn`, and `m_getSongInfoBtn`) enabled. All other preparation actions remain blocked until the server starts the round.

## Human scoring attempt lifecycle

`PlayLayer::destroyPlayer()` is also invoked by Geometry Dash for the internal anti-cheat verification spike. Vanilla Geometry Dash returns from that branch without killing the player. Alpha.21 reported that callback as a real Ranked attempt end, which could close the human attempt near 0% while gameplay continued. Alpha.22 mirrors the vanilla anti-cheat-spike guard before reporting any Ranked attempt end.

## Live spectator progress

The server now exposes spectator mode in two cases:

1. Existing two-clear `LAST_ATTEMPT_WINDOW`: the trigger side cannot start another attempt and watches the target side.
2. Normal round final-start window expiry: when the round is settling, the viewer has no active attempt, and the opponent still has an accepted active attempt, the viewer becomes a read-only spectator.

The playing client continues sending ephemeral attempt progress. The spectator polls match state at approximately 150 ms while spectator mode is active and displays the opponent username and current percent. Telemetry does not create attempts or mutate committed score by itself.

## Scope

No Corum Integration source or Apps Script configuration changes are required by alpha.22.
