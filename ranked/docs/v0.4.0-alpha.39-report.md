# Corum Ranked v0.4.0-alpha.39 report

## Scope

alpha.39 fixes the Attempt event transport and the FINAL/LAST ATTEMPT boundary issues reproduced by the supplied alpha.38 logs. It does not change scoring, MMR/RP, map-pool selection, bans, the two-Clear rule, or the database schema.

## 1. Attempt End HTTP 400 and blocked Clears

The logs show successful End acknowledgements only for exact `0` and `100` values. The first raw non-integer Geometry Dash value, including `0.019547325102880658` and `24.505414197332836`, exceeded `AttemptEndDto`'s three-decimal contract and received HTTP 400. The client previously retried that deterministic request once per second forever, so its serialized FIFO never delivered the Starts, Ends, or second Clear behind it.

alpha.39 normalizes progress to `[0, 100]` with at most three decimal places on both sides of the protocol. The client sends the normalized value and uses it for its optimistic score. The server also normalizes valid in-range input before validation as a compatibility defense. Deterministic 4xx Attempt failures are now removed from the FIFO; only transient network/5xx/408/425/429 failures retry.

## 2. Phantom first attempt

`PlayLayer::init()` previously journaled Attempt Start before Geometry Dash's delayed initialization reset (about 100-150 ms in the supplied logs). That reset was then recorded as End 0, followed by another Start. alpha.39 lets resets inside a bounded 500 ms scene-setup window remain vanilla-only until a genuine attempt event occurs, then journals one stable Ranked Start. A real early death or Clear uses the existing End self-recovery path, so it is still recorded rather than discarded.

## 3. Three-minute plus ten-second start window

While a poll still reports `ROUND_PLAYING`, its `deadlineAt` is the normal three-minute boundary. A clamped timer cannot distinguish an exact expiry from time after expiry, which produced `00:00` until the next poll changed the state.

alpha.39 retains a signed server-clock delta. At 3:00 the HUD immediately derives `FINAL ATTEMPT 10.0`, counts down in tenths, and retains `0.0` after the start window closes. New starts are permitted only before 3:10, including when the state poll is stale. An attempt that was armed or started in time remains valid until it naturally ends.

The rules regression suite explicitly verifies both intersections requested during diagnosis:

- a legally active attempt may deliver its second Clear after 3:00, which creates a fresh ten-second LAST ATTEMPT window from the accepted Clear time;
- when a two-Clear LAST ATTEMPT window begins before 3:00 and crosses 3:00, that LAST ATTEMPT deadline supersedes the original normal deadline. An attempt started inside it may finish after both deadlines.

Debug Bot Match retains the existing separate settling behavior: an already active Bot attempt continues, but the Bot cannot create a new attempt after the window closes.

## 4. Completion and spectator transition

Calling `PlayLayer::onQuit()` beneath a live Geometry Dash completion overlay could orphan the `EndLevelLayer` and leave Replay/Menu controls inert. alpha.39 lets the completion layer exit through Geometry Dash's own Menu path when authority switches to spectator/result state. Replay is also redirected to Menu whenever a new attempt is closed, including a pending local second Clear or an expired FINAL/LAST window.

While the second-Clear End acknowledgement is still in flight, the Ranked screen now shows `CLEAR RECORDED / SYNCING RESULT` instead of incorrectly implying that map metadata or the local level payload is missing. Once acknowledged, normal PvP enters the opponent live spectator screen; Bot Match follows its existing Bot-specific settling simulation.

## 5. Launch and audio path

The current source already opens the real `LevelInfoLayer` and programmatically activates its real Play button. alpha.39 preserves that path and does not construct `PlayLayer` directly. Match music remains alive through `STARTS IN` and LevelInfo, then fades only after the real `PlayLayer` initializes.

## 6. Validate Corum Ranked Actions fixture

The GitHub workflow does not read the operator's live Google Spreadsheet. `validate-ranked-config.mjs` creates an isolated mock sheet in Actions. Its fixture still populated only one alternate map code after the production validator began requiring an alternate code for every Ranked Pool row, so the job failed with generated canonical IDs such as `11001`, regardless of the values entered in the real sheet.

alpha.39 gives every mock Ranked Pool row a unique alternate code and updates the playable-ID assertions. This changes only the local Actions test fixture; it does not overwrite or migrate the live Spreadsheet.

## Deployment and compatibility

- Client manifest: `v0.4.0-alpha.39`
- Required server client gate: `v0.4.0-alpha.39`
- Database migration: none
- Apps Script change: none

Deploy the alpha.39 server gate and client together. An alpha.39 client is intentionally rejected by an alpha.38 server gate, and vice versa.
