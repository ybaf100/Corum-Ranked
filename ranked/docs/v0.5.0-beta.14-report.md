# Corum Ranked v0.5.0-beta.14 implementation report

## Authority and compatibility

This release follows `v0.5.0-beta.13` and keeps the production server URL fixed at `https://corum-ranked.onrender.com`. No Corum-Ranked-Web source or Web canonical is part of this release.

## Death Match

Death Match has no Qualifying %. Each side receives exactly three authoritative Attempts. The server compares `max(progress_percent)` for each side, with Clear represented as 100%. A tie keeps the existing Death Match retry-map lifecycle. A fourth Attempt Start remains rejected. Existing persisted Attempt evidence and Death Match score columns are reused; no database migration is required.

The gameplay HUD repurposes the normal timer position for the local authoritative remaining Attempt count (`3 → 2 → 1 → 0`). That value decreases only after an Attempt End is accepted by authority. Per-side `Attempts : n/3` remains a separate Start-usage display.

## Viewer-relative opponent lifecycle

Match polling exposes ephemeral viewer-relative opponent state:

- `opponentProgress`
- `opponentFinished`
- `opponentPractice`

Attempt Start resets display progress to 0 and clears Finished. Accepted progress updates the raw integer percentage. Attempt End latches Finished while retaining the final raw progress internally. Practice presence uses a separate idempotent runtime update, is not stored in the database, and cannot mutate score, Attempt authority, round timers, or the opponent's PlayLayer/state.

When the third Death Match Attempt immediately resolves the match, the terminal `MATCH_RESULT` response still preserves the final viewer-relative opponent lifecycle projection so `opponentFinished` does not regress to false on the last authoritative End.

## Placement

Placement keeps the existing Top-2 scoring and Attempt-End persistence rules. The client now renders a fixed upper-right Top 2 presentation built from authoritative completed Attempts plus the active provisional Attempt. Row identity is stable by Attempt ID; order changes animate without rebuilding score authority. Provisional progress never commits persisted Map Grade.

## Jukebox and Level Prepare

`fleym.nongd` is an optional enabled allowlist entry, not a required dependency. When available, Level Prepare permits the intended song-widget interaction while retaining all existing environment and CBF restrictions. Effective song readiness continues to rely on Geometry Dash's resolved `MusicDownloadManager::pathForSong(songId)` flow. Level options needed for LDM/Disable Shake may be opened without resetting authoritative match state or clock.

## Transition hitch work

Ranked audio now prewarms reusable FMOD stream handles outside competitive transition callbacks where possible, avoiding repeated synchronous stream creation during Round 3, Death Match, Stage Result, and final-result handoffs.

A low-cost transition tracer records monotonic timing boundaries including server-state receipt, audio mode/prewarm/channel start, rank texture decode, Stage merge node build, and first gameplay frame. This provides actual-device evidence without changing the existing 10-second Prepare period or state machine semantics.

## External Rank Asset Pack infrastructure

The client contains versioned external asset-cache infrastructure under the mod save directory. It supports Google Drive redirect download, HTML/login/quota rejection, byte-size validation, ZIP signature validation, SHA-256 verification, temporary extraction, required-asset validation, and verified activation. Renderers prefer verified external cache and retain bundled assets as permanent fallback.

The Resource Gate now reports Rank Visuals alongside Ranked audio resources. An external visual pack failure does not block Ranked because bundled PNG resources remain authoritative fallback; only an active external-pack download waits at the gate. Failed visual-pack downloads stop automatic retry loops and require an explicit retry.

The downloader uses Geode 5.8.2 string-view APIs portably on all client targets by explicitly materializing response headers as `std::string` before ordinary string inspection.

Production external downloading intentionally remains inactive until real authoritative `assetPackVersion`, Drive file ID, SHA-256, and byte-size metadata are provided. No placeholder production values are embedded.

## Release gate

The release is not considered merge-ready until rules, server, database/config validators, client domain tests, Debug Bot domain tests, and official/debug multi-platform Geode builds all pass on the beta14 branch.
