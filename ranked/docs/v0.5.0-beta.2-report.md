# Corum Ranked v0.5.0-beta.2 report

## Supplied-log diagnosis

The client received `MATCHED -> BAN_PHASE -> ROUND_PREPARE -> ROUND_PLAYING` normally and armed level `91989690`. It then logged `Activating Ranked Play selector` without a `PlayLayer::init` or LevelInfo exit. While that launch was latched, authority changed to `DEATHMATCH_PLAYING` with level `94373505`; the old page remained until its watchdog expired, after which the new page repeated the same failure three times.

This excludes queue, Ready, map download, and server start authorization as the primary failure. The failing boundary is the programmatic callback stored on the visible LevelInfo Play item on the iOS hook stack.

## Client fix

- Automatic Play now activates a temporary selector whose target is the currently active Corum Ranked `LevelInfoLayer` instance.
- The selector forwards through vanilla `LevelInfoLayer::onPlay`; Ranked still never constructs `PlayLayer` directly.
- If proxy activation is rejected, the same vanilla callback is invoked directly once instead of waiting through three silent retries.
- If the authoritative map/context changes during launch, the obsolete gate and watchdog are cancelled and the old LevelInfo scene is popped immediately.
- Added logs for proxy forwarding, fallback use, and obsolete-context disposal.

## Included hotfixes

- `CCParticleFire` uses the cocos particle header required by iOS builds.
- `RatingEventView` is fully qualified as `corum::ranked::RatingEventView`.
- The existing Ranked workflow exposes a manual Debug Bot input and checks that every combined platform binary actually contains or excludes the debug marker according to the selected mode.

## Deployment

1. Deploy the beta.2 server so `REQUIRED_RANKED_CLIENT_VERSION` matches the client.
2. Build `Build Corum Ranked Mod`. Use `debug_bot_match=true` only for a development Bot build.
3. Install the resulting `hwanhee1.corum_ranked.geode` on the test client.
4. Confirm the log contains `source=instance-selector-proxy`, followed by `Ranked LevelInfo onPlay forwarded to vanilla` and `PlayLayer::init`/attempt-start activity.

No database migration or Apps Script update is required from beta.1.
