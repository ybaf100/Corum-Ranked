# v0.5.0-beta.9 Solo Stage Placement

## 서버 경계

Placement는 `PlacementModule`과 `PlacementService`가 소유하는 별도 PostgreSQL aggregate다. 일반 PvP의 Match/Ready/Ban/BO3/Deathmatch/rating 상태 머신과 5분·3 Clear 규칙은 변경하지 않는다. 배치 미완료 프로필만 일반 Queue와 Debug Bot 진입이 차단된다.

## 진행과 점수

- 5 Stage × 2 Map이며 같은 Stage의 canonical map은 반드시 다르고, Run 전체에서는 미사용 맵을 우선한다.
- 시작 화면은 각 `POOL 1`~`POOL 6`에 qualifying 중앙값 기준의 결정적 Reference Map 하나를 보여준다. Pool 표기는 언어와 무관하게 영문으로 유지한다.
- Placement Map만 180초 Main Time, 10초 Final Attempt 시작 창, 2 Clear 종료를 사용한다.
- 기존 `scoreAttempt()`를 그대로 사용하며 Clear는 250점이다.
- Map Score는 유효 Attempt의 awarded score 상위 2개 합계이며 최대 500점이다. 2 Clear는 항상 500점·S·즉시 종료다.
- 기본 Grade 기준은 `S≥425`, `A≥350`, `B≥250`, `C≥150`, 나머지 D다.
- active Attempt의 progress는 서버가 임시 Attempt evidence로 계산한 provisional Top 2 Map Score만 갱신한다. Grade는 Attempt End가 확정된 뒤에만 바뀐다.

Stage Score는 두 Map Score의 평균이다. S/S만 +2, 나머지 S와 A는 +1, B는 유지, C는 -1, D/D만 -2, 나머지 D는 -1이며 Pool은 1~6으로 clamp한다. 최종 Rating은 10개 Map과 5개 Stage 전체 evidence를 반영하고 기존 cutoff ±15 회피 및 Placement Reveal을 재사용한다.

## 준비·복구·스킵

`MAP_PREPARE`는 DB에 시작/마감/Ready 시각을 저장한다. 10초 카운트다운 시작과 동시에 정확한 GD 레벨을 로딩하고, 5초 남았을 때 실제 LevelInfo를 공개하며, Ready 여부와 무관하게 카운트다운 전에는 MAP_PLAYING으로 넘어가지 않는다. 마지막 10초에 시작된 active Attempt는 deadline 뒤 `MAP_SETTLING`에서 Death/Clear까지 정산된다.

스킵은 Run이 아직 없을 때만 허용한다. 서버가 Hidden MMR 150과 RED 150 LP를 exactly-once 기록하고, 확인되지 않은 결과는 일반 Placement Reveal과 동일하게 `/placement/active`에서 복구된다.
