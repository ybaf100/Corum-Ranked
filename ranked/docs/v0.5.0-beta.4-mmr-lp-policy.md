# Corum Ranked v0.5.0-beta.4 MMR·LP 반영 정책

이 문서는 서버가 경기 결과를 확정할 때 Hidden MMR과 표시 Ranked Score(LP)에 실제로 반영하는 요소 전체를 정리한다. 클라이언트는 Hidden MMR이나 MMR 변동량을 받지 않는다.

## 1. 최초 Hidden MMR

- 프로필이 처음 만들어질 때 현재 CSMP 티어에 대응하는 `Ranked CSMP Seed`를 Hidden MMR로 한 번만 적용한다.
- `NONE`을 포함한 모든 실제 CSMP 티어에 유한한 Seed 값이 있어야 queue가 열린다.
- 기존 프로필은 Seed 설정이나 CSMP 티어가 바뀌어도 다시 시드하지 않는다.
- 배치 중 화면 LP가 0이어도 매칭, 상대 탐색, 경기 티어와 맵 풀은 Hidden MMR snapshot을 사용한다.

## 2. Hidden MMR 경기 변동

### 2.1 기본 Elo 입력

- 경기 직전 양쪽 Hidden MMR
- 승자 또는 무승부 결과: 승리 `1`, 무승부 `0.5`, 패배 `0`
- 배치 진행 횟수: 배치 중이면 `placementKFactor`, 완료 후에는 `regularKFactor`
- `expectedScoreDivisor`
- `deltaRounding`: `NEAREST`, `FLOOR`, `CEIL`

기본 기대 승률은 다음과 같다.

```text
rawExpected = 1 / (1 + 10 ^ ((opponentMMR - ownMMR) / expectedScoreDivisor))
expected = clamp(0.5 + (rawExpected - 0.5) × mmrOpponentStrengthWeight, 0, 1)
```

`mmrOpponentStrengthWeight`는 0~2다.

- `0`: 상대 강도를 무시하고 항상 기대 승률 50%로 계산
- `1`: 표준 Elo 강도
- `2`: 50%에서 벌어진 거리를 2배 반영하되 0~100%로 제한

따라서 강한 상대를 이기면 MMR 상승이 커지고, 약한 상대에게 지면 하락이 커진다. 반대 상황은 변동이 작아진다.

### 2.2 경기력 배율

일반 경기 MMR 변화에는 다음 값이 함께 반영된다.

- 모든 일반 Round와 Death Match의 확정 Score 합계
- 모든 일반 Round의 Clear 합계와 Death Match 유효 Clear 횟수
- Score 격차: `abs(A-B) / max(1, abs(A), abs(B)) × scoreMarginMaxBonus`
- Clear 격차: 같은 정규화 방식 × `clearMarginMaxBonus`
- 승자가 총 Score 또는 총 Clear 중 하나라도 패자보다 낮으면 `outcomeDisagreementFactor` 적용
- 연승·연패: 같은 방향의 두 번째 결과부터 `streakStep`씩 증가하고 `streakMaxBonus`에서 제한

결정 결과의 일반식은 다음과 같다.

```text
marginFactor = 1 + scoreMarginBonus + clearMarginBonus
performanceFactor = outcome disagreement
  ? min(1, marginFactor × outcomeDisagreementFactor)
  : marginFactor

streakFactor = 1 + min(streakMaxBonus, (nextStreakCount - 1) × streakStep)
delta = round(K × (actual - expected) × performanceFactor × streakFactor)
```

- 무승부는 Score/Clear margin 보너스를 받지 않는다.
- 연승은 상승 폭, 연패는 하락 폭을 키운다.
- 경기 승패와 총 Score/Clear 우세가 엇갈리면 결정승 보너스로 바뀌지 않도록 `performanceFactor`를 1 이하로 제한한다.
- 양쪽은 각자의 K-factor, 기대 승률, streak 상태로 별도 계산되므로 항상 완전한 zero-sum일 필요는 없다.

## 3. PERFECT WIN 최대 Hidden MMR

다음 조건을 모두 충족한 승자만 `PERFECT WIN`이다.

- 서버의 자연스러운 Bo3 결과로 승리
- 한 라운드도 패배하지 않음
- 최소 한 번의 결정승이 있음
- 모든 결정승이 승자 3-Clear 후 상대의 LAST ATTEMPT가 만료된 `LAST_ATTEMPT_EXPIRED`

무승부 라운드는 허용한다. Force Win/Lose, ready·reconnect·resource 몰수승, 일반 Score 승리, Death Match 승리는 인정하지 않는다.

승자는 기존 공식의 이론상 최대 획득량을 받는다.

```text
maximumMmrGain = round(
  K × (1 + scoreMarginMaxBonus + clearMarginMaxBonus)
    × (1 + streakMaxBonus)
)
```

이 값은 기대 승률 항의 이론상 최대치인 `(actual - expected) = 1`을 사용한 것이다. 패자는 PERFECT 보정 없이 일반식으로 계산한다. 현재 검증 설정이 `regularKFactor=32`, `placementKFactor=64`, Score/Clear 최대 보너스가 각각 `0.35`, streak 최대 보너스가 `0.25`이면 정규 `+68`, 배치 중 `+136`이다.

## 4. 배치와 표시 LP

- 배치 중 표시 LP는 0이며 API와 UI에서 숨긴다.
- 경기 결과마다 배치 경기 수는 증가한다.
- 결정승·패만 순서대로 `O/X`에 기록하고 무승부는 표식을 추가하지 않는다.
- 마지막 배치 경기 뒤 Hidden MMR 반영 후 값을 반올림해 최초 LP를 정한다.
- 각 티어 커트라인의 포함 구간 `cutoff ±15` 안이면 위 티어로 바로 배치하지 않고 `cutoff - 16` 이하로 내린다.
- 배치 완료 경기는 승급전을 시작하지 않는다.

배치 중 PERFECT WIN은 최대 Hidden MMR을 받지만, LP는 기존 배치 규칙대로 마지막 배치 결과 전까지 계속 숨긴다.

## 5. 일반 표시 LP 변동

무승부는 LP 변화가 없다. 배치와 진행 중 승급전이 아닌 결정 경기에는 다음 요소를 반영한다.

### 5.1 Hidden MMR과 현재 LP의 차이

```text
gapCorrection = clamp(
  1 + (hiddenMmrAfter - visibleLpBefore) / visibleScoreGapDivisor,
  visibleScoreMinFactor,
  visibleScoreMaxFactor
)

gapFactor = win ? gapCorrection : 2 - gapCorrection
```

- Hidden MMR이 LP보다 높으면 승리 상승을 키우고 패배 하락을 줄인다.
- Hidden MMR이 LP보다 낮으면 승리 상승을 줄이고 패배 하락을 키운다.

### 5.2 상대 강도

경기 전 양쪽 Hidden MMR로 위 Elo 기대 승률을 다시 계산하되 `visibleScoreOpponentStrengthWeight`를 사용한다.

```text
opponentFactor = win ? 2 × (1 - expected) : 2 × expected
movementFactor = clamp(
  gapFactor × opponentFactor,
  visibleScoreMinFactor,
  visibleScoreMaxFactor
)

lpMagnitude = max(1, round(visibleScoreBaseChange × movementFactor))
```

`visibleScoreOpponentStrengthWeight`도 0~2다. 강한 상대에게 승리하면 LP 상승이 커지고 패배하면 하락이 작다. 약한 상대에게 승리하면 상승이 작고 패배하면 하락이 크다.

Hidden MMR과 LP가 2500으로 같고 `expectedScoreDivisor=400`, 상대 강도 가중치 `1`, LP base `25`, 최소/최대 배율 `0.5/1.5`인 예시는 다음과 같다. 이 값들은 티어 커트라인에 걸리지 않는 일반 LP 계산 예시다.

| 자신의 MMR | 상대 MMR | 승리 LP | 패배 LP |
|---:|---:|---:|---:|
| 2500 | 2000 | +13 | -38 |
| 2500 | 2500 | +25 | -25 |
| 2500 | 3000 | +38 | -13 |

### 5.3 PERFECT WIN 최대 LP

일반 LP 계산 구간의 PERFECT WIN 승자는 상대 강도와 MMR-LP 차이에 관계없이 `visibleScoreMaxFactor`를 사용한다.

```text
maximumNormalLpGain = round(visibleScoreBaseChange × visibleScoreMaxFactor)
```

기본 LP 설정 `25 × 1.5`에서는 `+38 LP`다. 단, 티어 커트라인·승급전·배치 상태의 기존 상태 전이와 고정 점수 규칙이 우선한다.

## 6. 승급과 강등 예외

- 승리 후 예상 LP가 다음 티어 커트라인에 닿으면 `cutoff - 1`에서 승급전을 시작한다. 승급전을 발생시킨 경기는 승급전 승수에 포함하지 않는다.
- 승급전 중 무승부는 결과 수와 LP를 바꾸지 않는다.
- 승급 성공 시 `cutoff + promotionScoreBonus`, 실패 시 `max(sourceTierMin, cutoff - promotionFailurePenalty)`로 이동한다.
- 승급전 중 경기별 일반 LP·상대 강도 배율은 적용하지 않고 승급전 상태 규칙을 사용한다.
- 패배 예상 LP가 현재 티어 바닥을 넘으면 바닥에서 보호한다.
- Hidden MMR도 바닥 미만이면 첫 경고 후 다음 결정 패배에서 `currentCutoff - demotionScorePenalty`로 강등한다.
- 최하위 티어이거나 Hidden MMR이 현재 바닥 이상이면 바닥에서 보호하고 강등 경고를 만들지 않는다.

## 7. MMR·LP에 반영하지 않는 항목

- 클라이언트가 표시한 타이머나 로컬 시각
- 승인되지 않은 attempt와 무효 attempt의 Score/Clear
- 관전용 상대 현재 progress telemetry
- 맵 제목, 제작자, 음악, 클라이언트 FPS
- 수동으로 제출한 winner나 MMR 값: 해당 API 자체가 없음
- 표시 LP 0이라는 이유만으로 배치 플레이어를 0 MMR로 취급하는 동작

서버는 PostgreSQL transaction 안에서 결과를 한 번만 반영하고 `result_applied_at`으로 중복 적용을 차단한다.
