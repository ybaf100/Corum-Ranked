# v0.5.0-beta.8 Solo Stage Placement

## 경계

배치는 Bot 또는 가상 PvP Match가 아니다. `PlacementModule`과 `PlacementService`가 별도 PostgreSQL aggregate를 소유하며, 일반 `MatchService`의 양쪽 플레이어, Ready/Ban/BO3/Deathmatch/rating 상태 머신은 변경하지 않는다. 배치 미완료 프로필만 일반 Queue와 Debug Bot 진입이 차단된다.

## 진행과 점수

- 시작 Pool은 1~6 중 사용자가 선택하지만 첫 Stage 맵 범위만 결정한다.
- 5 Stage × 2 Map이며 같은 Stage의 canonical map은 반드시 다르다. Run 전체에서는 미사용 맵을 우선한다.
- 각 Map은 기존 300초 Main Time, 10초 Final Attempt 시작 창, 3-Clear 종료와 `scoreAttempt()`를 그대로 사용한다.
- Map Score는 유효 Attempt의 awarded score 상위 3개 합계다. 부족한 칸은 0이고 최대는 750이다.
- 3 Clear는 다른 계산보다 우선해 Map Score 750, Grade S, 즉시 Map 종료다.
- Grade는 `S≥638`, `A≥525`, `B≥375`, `C≥225`, 나머지 D가 기본 정책이며 Apps Script/config snapshot 한 곳에서 조정한다.
- active Attempt의 progress telemetry는 Grade를 절대 바꾸지 않는다. Attempt End가 서버에서 확정된 뒤에만 Top 3, Map Score와 Grade를 갱신한다.

Stage Score는 두 Map Score의 단순 평균이다. S/S만 +2, 나머지 S와 A는 +1, B는 유지, C는 -1, D/D만 -2, 나머지 D는 -1이며 Pool은 1~6으로 clamp한다.

## 최종화

10개 Map의 score, grade, 실제 Pool과 5개 Stage aggregate를 모두 configurable Pool anchor에 반영해 Placement Rating을 계산한다. 이 값을 Hidden MMR 초기값으로 변환한 뒤 기존 tier/LP finalization을 재사용한다. 각 non-lowest tier cutoff의 `[cutoff-15, cutoff+15]`는 금지하고 해당되면 `cutoff-16`으로 내리며 tier floor, `TIER - N LP`, `PLACED`, `RankTransitionLayer::Placement`를 유지한다.

## UI와 복구

Placement PlayLayer만 왼쪽 아래 Qualifying을 숨기고 Grade 한 글자 이미지만 표시한다. `placement-grade-s/a/b/c/d.png` 로드 실패 시 같은 노드에서 텍스트로 대체한다. 같은 Grade는 무연출, 상승은 약 0.3초 pop, 하락은 짧은 fade다. Stage Result는 양쪽 Map Grade를 중앙으로 합친 후 최종 Grade를 보여주며 S/A/B는 기존 ResultWin, C/D는 ResultLose를 재사용한다.

Run/Map/Attempt/stateVersion/config snapshot/deadline/heartbeat/raw score/Grade/finalization/ACK는 모두 DB에 남는다. 활성 Attempt, Map 1 완료, Map 2 완료, Stage Result, 서버 재시작 및 확인 전 Placement Result는 `/placement/active`와 `/state`로 이어간다.
