# Corum Ranked v0.4.0-alpha.32 report

## Scope

Ranked BGM playback reliability after the alpha.30 private-cache downloader change. Download transport and all Ranked gameplay/server rules remain unchanged.

## Root cause

The client treated `FMODAudioEngine::playMusic()` as successful without verifying that a live music channel was actually created. Before calling it, alpha.31 only used `fadeOutMusic()` on the existing Geometry Dash menu track. That fade did not guarantee that the old music slot had been removed, so the new Ranked stream could fail to take ownership while the client still set `m_ownsMusicChannel=true` and `m_playingKey`. Every later poll then skipped playback as "already playing", leaving Ranked permanently silent.

A second reliability issue was that a downloaded response was considered cached solely from its file size. A non-audio HTTP body larger than 1 KB could therefore pass the resource gate and fail only at FMOD playback time.

## Fix

- Keep the configured fade-out delay, then call `stopAllMusic(true)` immediately before starting the Ranked stream.
- Unpause the main music channel group and restore `FMODAudioEngine::m_musicVolume` before playback.
- Verify after a short delay that an active main music channel is actually playing.
- Retry failed starts up to two times with a zero-second retry fade; do not preserve the false "already playing" state when verification fails.
- Apply configured `startSeconds` only after the new music channel is live.
- Validate private-cache files using common audio signatures (MP3, Ogg, FLAC, WAV, MP4-family) in addition to minimum size.
- Hard-stop Ranked music before restoring normal Geometry Dash menu music on exit/resource-gate restoration.

## Unchanged

No database migration, Apps Script schema change, Ranked server behavior, scoring/MMR rule, map-pool rule, attempt transport rule, FINAL/LAST ATTEMPT rule, or Debug Bot rule changed in alpha.32.
