# Corum Ranked v0.4.0-alpha.33 report

## Scope

alpha.33 is a reliability release for authoritative attempt delivery, Death Match visual-attempt accounting, inter-round presentation time, and Ranked BGM on iPadOS/iOS.

## 1. Round attempt delivery / Score 0 race

The client still preserves visual Start/End order in its FIFO journal, but every standard-round visual Start now also sends an out-of-band **Start Lease** immediately. The lease does not award score and cannot create an attempt by itself.

The server persists those leases in PostgreSQL (`ranked_attempt_start_leases`). A valid lease observed before the real start deadline prevents the round from being finalized while the serialized authoritative Start/End request is still catching up. This protection survives a Render process restart.

Additional transport changes:

- result polling no longer discards a completed local Start/End journal;
- newest Start Lease traffic preempts an older slow lease request so an old HTTP wait cannot head-of-line block the current visual attempt;
- `/attempt/start` is idempotent even if its original ACK was lost and the match state later advanced;
- `/attempt/end` acknowledges an already-committed round attempt by its unique End event before advancing clocks, so a lost End ACK cannot become a false result-state rejection;
- Death Match Start/End retries are also idempotent across `DEATHMATCH_RESULT` / `MATCH_RESULT`, preventing an ACK-loss retry from consuming or discarding a visual attempt journal entry;
- FINAL/LAST ATTEMPT semantics are unchanged: the 10-second window limits **Start**, not gameplay duration.

Database migration required for an existing alpha database:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f ranked/migrations/0002_attempt_start_leases.sql
```

Apply the migration before deploying the alpha.33 server.

## 2. Death Match exactly three visual attempts

The old client reserved the next Death Match attempt before the next visual attempt actually existed. That could make the local budget reach 3 while the server still correctly reported 2/3, causing the third visual attempt to be blocked.

alpha.33 removes pre-reservation. A local Death Match attempt is counted only when `reportAttemptStart()` creates the new visual Start journal entry. The popup also displays the greater of authoritative/server usage and the current local visual usage for the viewer, avoiding a temporary 2/3 versus 3/3 mismatch while an ACK is in flight.

The server remains authoritative and continues to reject attempt 4 with `DEATHMATCH_ATTEMPTS_EXHAUSTED`.

## 3. Five-second next-map card

`ROUND_PREPARE` and `DEATHMATCH_PREPARE` now keep the Ranked map/status card visible for the first five seconds. The existing total 10-second preparation flow is preserved: after those five seconds the normal Geometry Dash LevelInfo/resource gate receives approximately the remaining five seconds.

Ready is still not submitted until the resource gate completes, so the authoritative round timer does not run while the map card is being read.

## 4. Ranked BGM / iPadOS lifecycle

Ranked BGM no longer relies on `FMODAudioEngine::playMusic()` for playback. The Ranked audio manager owns an FMOD streaming `Sound` and `Channel` directly.

- downloaded songs prefer Geometry Dash's canonical `MusicDownloadManager::pathForSong(songId)` path;
- existing valid private-cache songs are migrated when possible;
- the FMOD master output group is normalized to active/unmuted while Ranked is active;
- a one-second watchdog verifies that the playback position actually advances, not merely that FMOD reports a channel as "playing";
- looped BGM is recreated if the owned channel dies;
- `AppDelegate::pauseSound()` explicitly pauses the Ranked-owned direct channel, and `resumeSound()` triggers deferred recovery after iPadOS/iOS foreground resume;
- Ranked BGM volume is `Geometry Dash Music Volume × 0.80`;
- gameplay handoff stops the Ranked-owned channel before Geometry Dash takes over level audio.

## 5. Validation

Validated in this source tree:

- all server/test TypeScript files pass syntax transpilation with TypeScript;
- standalone C++ domain tests pass with `-Wall -Wextra -Wpedantic -Werror`;
- Ranked Apps Script config validation passes;
- legacy Corum Integration record-sheet compatibility validation passes.

Not executable in this environment:

- full NestJS/Vitest integration suite, because npm dependency installation could not complete in this runtime (registry access stalled/timed out);
- native Geode Windows/Android/iOS build, because `GEODE_SDK` is not installed here.

The new integration coverage is included in source, including a normal-round second-Clear lease race that polls beyond the real start deadline before the serialized Start arrives, persistent Start Lease recovery across a recreated `MatchService`/in-memory runtime, End retry idempotency after the final result, and the existing exact-3 / reject-4 Death Match flow.

## Unchanged

Scoring formula, MMR/RP rules, tier boundaries, map pool, ban rules, two-Clear rule, FINAL/LAST ATTEMPT start-window duration, and Debug Bot rating policy are unchanged. Apps Script schema is unchanged. Corum Integration is unchanged.
