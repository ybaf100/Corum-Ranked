# v0.4.0-alpha.5 빌드 수정 보고서

## 원인

alpha.4 계열 Debug Bot UI 중 일부 호출부는 `startDebugBotMatch(password, options)`를 호출하지만,
`RankedRuntime`의 최신 선언/정의는 `startDebugBotMatch(options)` 하나만 제공해 모든 Geode 타깃에서
`too many arguments to function call` 컴파일 오류가 발생할 수 있었다. 이 오류는 Android64 전용이 아니라
공통 C++ 소스의 API 불일치이므로 Windows/iOS/Android32/Android64 모두에 영향을 준다.

## alpha.5 수정

- 기본 API `startDebugBotMatch(DebugBotMatchOptions options)`는 그대로 유지한다.
- CMake에서 alpha.4의 stale `src/debug/DebugBotPopup.cpp` 경로를 빌드 대상에서 제외해, 덮어쓰기 업데이트 후 중복 DebugBotPopup이 남아 있어도 공통 빌드가 깨지지 않게 했다.
- 호환 overload `startDebugBotMatch(std::string const& password, DebugBotMatchOptions options)`를 추가한다.
- 호환 overload는 전달받은 password를 `options.password`에 넣은 뒤 기본 API로 위임한다.
- 따라서 새 UI의 단일-options 호출과 이전 alpha.4 UI의 2-argument 호출이 모두 같은 서버 요청 경로를 사용한다.
- password 검증을 제거하거나 우회하지 않는다.
- manifest/server/rules workspace 버전을 `v0.4.0-alpha.5` / `0.4.0-alpha.5`로 맞췄다.

## 검증 범위

이 전달본에서는 Geode SDK가 로컬 환경에 없어 플랫폼별 `.geode` 바이너리를 직접 생성하지 않았다.
대신 저장소에 포함된 C++23 domain test, Node rules/server tests, typecheck/build, Apps Script 검증을 실행한다.
최종 Windows/iOS/Android32/Android64 바이너리는 기존 `build-ranked-mod.yml` matrix에서 검증해야 한다.
