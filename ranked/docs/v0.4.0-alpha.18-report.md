# Corum Ranked v0.4.0-alpha.18

## Scope

Client attempt/scoring reliability correction based on `v0.4.0-alpha.17`. Server scoring rules, database schema, Apps Script config, Ban resolution, and Corum Integration are unchanged.

## Failure paths found in alpha.17

The server/rules path already accepts decimal Qualifying and authoritative Clear scores, but the Geode client contained multiple paths where a valid visual attempt could fail to reach that server path:

1. `PlayLayer` set `attemptEndReported = true` **before** `RankedRuntime::reportAttemptEnd()` proved that the end was queued. If the runtime rejected the call because the local start was missing or state/map timing was transient, the death/Clear was then permanently suppressed by the completion guards.
2. Live progress was ignored until `/attempt/start` had returned an `attemptId`. Fast attempts could therefore produce no telemetry before death/Clear.
3. Even when progress had been buffered locally, the successful start-ACK path reset `m_pendingProgress`, throwing that latest progress away.
4. Gameplay identity and Qualifying were read only from the latest polled `currentMap`, with no PlayLayer launch snapshot.

These were client transport/state-handling faults; authoritative scoring math remains `progress >= Qualifying -> floor(progress)` and `Clear -> 100 + Qualifying`.

## alpha.18 changes

- Added a gameplay-map snapshot armed immediately before the normal `LevelInfoLayer::onPlay()` path.
- `PlayLayer` identifies Ranked gameplay from that snapshot and retries Attempt Start registration until the local FIFO owns the attempt.
- Attempt Start/End reporting now returns local queue success.
- Death, manual reset, quit, `levelComplete()`, and `showCompleteText()` set the per-attempt end guard only after the end was actually accepted into the local transport.
- Attempt End can recover a missing local start while the authoritative state still permits new starts.
- Progress is buffered while the start request is awaiting ACK and is flushed after the authoritative attempt ID arrives.
- Start ACK no longer clears valid buffered progress.
- Progress telemetry uses the acknowledged attempt's pinned level ID rather than whichever map a later poll happens to expose.
- Local optimistic score/Clear calculation uses the gameplay snapshot's decimal Qualifying value.
- The match-flow integration test now commits a non-Clear attempt above Qualifying, verifies its stored score, then verifies the next Clear adds `100 + Qualifying`.

## Preserved behavior

- FIFO ordering for fast restart/death/Clear sequences.
- Decimal score support.
- LAST ATTEMPT active-attempt protection.
- Death Match three-attempt client/server budget.
- alpha.17 vanilla LevelInfo song-download gate.
- alpha.16 confirmed-ban and difficulty-color corrections.
- Corum Integration is untouched.

## Device regression checklist

1. On a map with Qualifying 20.1, reach 21% while alive: HUD own score must become `21`.
2. Die at 47%: committed/optimistic score must retain `47`, then reconcile to the server snapshot.
3. Clear once: HUD must add `100 + Qualifying` and the first Clear check must turn green.
4. Clear twice: second Clear check must turn green and the server must enter the 2-Clear/LAST ATTEMPT flow.
5. Rapidly restart/death several times while network ACKs are delayed: no attempt score may disappear.
6. Repeat the above on Windows, Android, and iOS builds as available.
