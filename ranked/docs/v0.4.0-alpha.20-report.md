# Corum Ranked v0.4.0-alpha.20

## Purpose

alpha.20 is a focused regression fix for the resource-preparation and player-score paths observed on a real Debug Bot Match.

## Map download fix

- Keeps Geometry Dash's vanilla `GameLevelManager::downloadLevel(levelId, false, 0)` path.
- A Ranked download is no longer considered complete from metadata alone; the level must contain playable `m_levelString` data and must not be marked `m_levelNotDownloaded`.
- The prepare screen polls the saved level on every refresh, so a lost `LevelDownloadDelegate` completion callback cannot permanently leave the UI on `DOWNLOADING...`.
- If another layer replaces the global GD level-download delegate while the request is active, Ranked restores its delegate.
- A request that has made no observable progress for 3 seconds is released and retried through the same vanilla downloader.
- The existing 30-second map resource deadline and Match Cancel/Loss policy remain unchanged.

## Player scoring fix

The current score formula remains:

- below Qualifying: `0`
- Qualifying through `69%`: `floor(progress)`
- `70%` through `99%`: `floor(progress) * 1.5`
- Clear: `200`

Additional client reliability changes:

- `PlayLayer` retrieves Qualifying from the map snapshot armed for the exact gameplay level instead of relying only on the mutable current match view.
- Unknown Qualifying no longer silently defaults to `100%` for provisional scoring.
- Attempt End uses the same immutable Qualifying fallback when creating its optimistic score.
- The provisional HUD enforces the current scoring invariant that every queued/accepted Clear contributes at least 200 points, preventing a delayed ACK from showing green Clear checks next to `Score : 0`.
- Attempt Start/End ACKs now emit diagnostic Geode logs including the final server-awarded score and rejection reason.
- Server scoring remains authoritative; the new client logic only fixes live/provisional presentation and transport observability.

## Debug Bot regression

Debug Bot Match does not use a separate human scoring path. Server integration coverage now explicitly verifies that the human side receives `400` authoritative points after two Clears (`200 + 200`) in a Debug Bot Match.

## Prepare score semantics

The large left/right numbers on Round/Death Match prepare screens now show Bo3 series round wins (`roundWinsA : roundWinsB`). They no longer display per-map point totals.

## Included CI correction

The alpha.19 Deathmatch unit-test expected value is updated for the current 70% multiplier / 200-point Clear formula.
