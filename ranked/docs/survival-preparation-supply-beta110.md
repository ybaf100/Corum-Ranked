## Confirmed causes and changes

**Status-board entry:** `handleAction(9)` previously set `m_manualMap`, advanced the navigation cancellation epoch, and the deferred launcher rejected `m_browsingBoard`. Preparation/reveal completion also depended on the visible map panel. Board/Back now only navigate. `advancePreparation()` keeps the exact match/round/generation/level logical reveal progressing while hidden, and cert/native/audio readiness reaches ASSETS_READY independently of visibility. Initial automatic entry can complete from the board, including after server PLAYING begins. Native ownership, current context, session/authority, surrender, modal and scene-transition checks remain. Already-entered contexts require the existing explicit re-entry path; duplicate automatic launch is rejected. No new countdown or server deadline is introduced.

**Free Play menu clock:** reused Draft PR #35 commit `53f0fb2f141922b7301c70970f8a31773b7cbb0e` with improvements. The original PR branch is preserved; its code was incorporated, not independently reimplemented or reset. `MenuLayer` consumes `roundRemainingMs()`, countdown and synchronized server age; shows R/FINAL/DM, preparation/GO or reconnecting, and hides result/cancelled clocks. It has no input handler. Four-corner transformed bounds protect visible native/third-party CCMenuItems, including disabled/rotated/scaled buttons. Placement prefers upper-left, then other available upper-screen positions; a fully occupied menu hides the timer. Native custom touch regions and physical layouts still need device inspection.

**Slow download:** online preparation timeout previously called the permanent forfeit path. Ready players retain the fast 15-second path; unready players become `entryDeferred`, distinct from network absence, rather than surrender. No official attempt is possible until valid ASSETS_READY and ENTERED. Late entrants use the existing shared startsAt/endsAt and receive no extra time. If nobody is ready, server-owned grace is capped at 60 seconds; clients cannot extend it by claiming DOWNLOADING. Existing all-absent zero-score behavior remains. Three replacements are allowed; further map-supply failure cancels the match without a new supply-related LP charge. Six failed actual map-selection jobs also cancel before play; failed prefetch does not interrupt PLAYING. Existing surrender and already-settled rewards are preserved.

**Audio:** the pinned Geode GJSongError mapping is FailedToFetch=1, NotAllowed=2, DownloadCancelled=3. Native callbacks previously discarded it. Tickets now retain the code/context and emit bounded structured diagnostics. Only NotAllowed establishes the permanent category; generic errors remain transient/metadata/unknown, never invented storage-full/deletion evidence. Success with a missing/empty effective file is cache-invalid. Retries stay capped at three and permanent errors stop automatic repeats. An active native request is drained, not unsafely replaced; foreign delegates/work remain owned by GD/their mod. Valid effective NONG/Jukebox paths still satisfy readiness. The failed-report context is separate from ready submission, fixing a discovered failure report that previously prevented later successful ASSETS_READY.

Reports carry category, native code, resource kind/ID and the authenticated current round/map context. Up to 32 resource reports per account/context are accepted. Stable account keys prevent session rotation from adding votes. At least two independent active human accounts must report the same native NotAllowed error within 120 seconds before a common failure invalidates a PREPARING/ENTERING map. No replacement occurs in COUNTDOWN/PLAYING. A map/resource quarantine expires after one hour; only server-extracted dependencies may quarantine that resource across other maps. Unknown extra native Song/SFX IDs can corroborate a failure of this map, but cannot poison unrelated maps. Generation advances; old preparation events and async results remain fenced. A prefetched map sharing the known bad dependency is discarded without rewriting official history.

The server currently extracts the documented primary song field 35. Full modern multi-song/SFX list mapping is not claimed verified: candidate `audioVerification=METADATA_ONLY`, and the native client still validates **all** m_songIDs/m_sfxIDs. No server probe is presented as proof that Newgrounds downloads succeed on every device. Generic Native errors do not expose enough evidence to distinguish deleted songs, filesystem capacity and every network cause; the explicit storage/unknown categories do not fabricate that information. No download restriction bypass was added.

## Durable candidate pool

Additive migration `0032_survival_preparation_supply.sql` creates operational bucket/candidate/report/quarantine tables and a bounded failure counter on sur_matches. No account, LP, AP, achievement, official record or old migration data is cleared. REQUIRED_MIGRATIONS and schema readiness include the additive schema.

Canonical buckets represent the exact difficulty range and minimum ID. Identical R3/R4 ranges, group overlaps and 16/64 eligibility predicates share storage; current rules yield 11 buckets. Each targets three READY certificates and requests replenishment below two. Records include downloaded-geometry SHA-256/bytes, native metadata/version, verification/expiry, dependency coverage, search source/page/ID stratum, reservation context and failure state. Raw geometry is not duplicated into PostgreSQL.

Reservations use a short global transaction/advisory lock and a unique RESERVED-level constraint. Confirmation is in the engine's authoritative selection/history transaction. Lease/context tokens reject stale confirmations; cancelled jobs release reservations. Startup reconciles already-adopted reservations against durable history and expires abandoned leases. Cached, unexpired certificates remain usable through upstream search outages. Exact metadata is checked again on resume; corrupt entries are isolated.

Certificates expire after six hours. The process runs one bounded verifier, prioritizing the active bucket. Real selection/startup/expiry work replenishes caches; no timer continually queries PostgreSQL to discover empty work. API backoff is exponential (30 seconds up to six hours, honoring stronger upstream Retry-After), with no SQL on failed external retries. Actual mutations/reservations/expiry do use SQL. Disposable retired metadata is capped at 64 records per bucket; READY surplus is put in cooldown and the in-memory exclusion set is bounded to 4,096. No player replay or official history is evicted. Empty-server code-level query suppression is tested; actual Neon compute suspension is a separate production observation, not asserted here.

The engine now preserves the global last **30** selections even when candidates are exhausted; the prior 30→20→10→0 fallback is removed. The provider gathers liked/recent/awarded results and distributed pages before choosing, deduplicates maps, then samples source/coarse-ID strata before geometry validation. Minimum 40M, existing difficulty/quality/length/Auto/Platformer and geometry constraints remain. ID strata are **not upload-year measurements**. Legacy type-4 relays are detected/cached for ten minutes, with accurate source/page provenance and local XL rejection.
