# Corum Ranked v0.4.0-alpha.40 report

## Scope

alpha.40 moves Ranked map configuration to an independent `sheet2`, changes new Ranked matches to three Clears in five minutes, repairs blank/default Geometry Dash level metadata, and makes the Ranked audio cache persistent across Android storage-path changes. Scoring values, MMR/RP, bans, the ten-second FINAL/LAST attempt-start windows, and the database schema are unchanged.

## 1. Independent Ranked map sheet

Corum Integration continues to read `sheet1` (or `MAPS_SHEET_NAME`). Ranked now reads `sheet2` by default, or `RANKED_MAPS_SHEET_NAME` when that dedicated property is set. Ranked does not silently fall back to `sheet1`: a missing or invalid Ranked tab produces an explicit configuration error so an accidentally empty map pool cannot be published.

`sheet2` must use the same base column layout as `sheet1`. `setupCorumRankedConfig()` adds the Ranked-only `Ranked Pool (1~6)` and `Qualifying %` columns to the selected Ranked tab. The isolated Actions validator now proves both sides of the routing: Ranked setup and reads affect `sheet2`, while the existing Corum Integration fixture continues to use `sheet1`.

## 2. Three Clears and five minutes

The fixed rules document is now `corum-ranked-v0.4` with:

- `roundDurationSeconds = 300`;
- `clearTarget = 3`;
- unchanged ten-second FINAL and LAST attempt-start windows.

The client HUD, optimistic attempt guard, result/history rendering, server spectator transition, Debug Bot scenarios, Apps Script response, and rules/server regression fixtures all use the same three-Clear target. `setupCorumRankedConfig()` migrates only untouched old defaults (`v0.3`, `180`, `2`) to (`v0.4`, `300`, `3`); operator-customized cells are not silently overwritten.

The deadline intersections retain the intended semantics:

- an attempt started within the normal five-minute window may finish after 5:00; if that finish is the third Clear, its acceptance creates a fresh ten-second LAST ATTEMPT start window for the opponent;
- if the third Clear starts LAST ATTEMPT before 5:00, that LAST deadline supersedes the original five-minute deadline; a legally started attempt may finish naturally after either deadline;
- crossing 5:00 without a third-Clear trigger uses the normal ten-second FINAL ATTEMPT start window.

During a rolling deployment, already-persisted `corum-ranked-v0.3` snapshots that have no `clearTarget` remain two-Clear matches. Newly created matches require the exact v0.4 three-Clear rules.

## 3. Blank/default LevelInfo metadata

Ranked creates a temporary `GJGameLevel` before Geometry Dash downloads the complete level. That shell inherited `GJLevelType::Default`, so vanilla `LevelInfoLayer` could treat it as a local/main-level object and render empty title/creator metadata even though the Ranked snapshot was available.

alpha.40 marks the shell and the downloaded replacement as `GJLevelType::SearchResult`, copies the authoritative Ranked title and creator before vanilla layer initialization, and repeats normalization after the download callback. The regular LevelInfo Play-button path remains in use; Ranked still does not construct gameplay directly.

## 4. Repeated Android resource downloads

The previous download path was derived from Geometry Dash's custom-song resolver. On Android that externally resolved path can differ after a provider/storage remount. Ranked also migrated its private copy to that path and deleted the private file, so the next entry could fail to find the same valid resource and reopen `RANKED RESOURCES`.

alpha.40 stores the authoritative downloaded file in the mod's persistent save directory under `ranked-audio/`. Geometry Dash's custom-song path is now only a compatibility mirror. Startup imports a valid legacy Geometry Dash copy when available, mirrors the persistent copy on a best-effort basis, and never deletes the authoritative private copy. A mirror failure therefore no longer reopens the resource gate.

## Deployment and compatibility

- Client manifest: `v0.4.0-alpha.40`
- Required server client gate: `v0.4.0-alpha.40`
- Rules document: `corum-ranked-v0.4`
- Database migration: none
- Apps Script update: required

Create `sheet2` with the `sheet1` layout, replace/redeploy `RankedConfig.gs`, and run `setupCorumRankedConfig()` once. Deploy the alpha.40 server gate and client together because client-version matching remains exact.
