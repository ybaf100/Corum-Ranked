## HUD와 관전 구현

- `PlayLayer.cpp`가 화면 크기에 따라 코너 anchor를 다시 계산한다. FPS는 좌측 최상단,
  자기 Score/승인 Clear 체크/중요 상태와 timer는 좌측 상단, 상대 Score/체크는 우측 상단,
  Match snapshot의 Qualifying은 좌측 하단이다.
- FPS는 `postUpdate` frame 간격을 `steady_clock`으로 관측한 `RenderFpsMeter` 값이며 physics,
  timestep, 게임 속도나 설정 FPS를 바꾸지 않는다. 표본 전에는 `FPS : -`다.
- 양쪽 Score와 Clear는 `GET .../state`의 서버 값만 사용한다. Clear 체크는 정확히 두 개이며
  `0=회/회`, `1=초/회`, `2=초/초`로 색을 바꾼다. 새 Round의 서버 snapshot이 0/0으로
  초기화한다.
- `ServerClock`이 `serverNow` offset을 관측하고 `deadlineAt`까지의 시간을 frame 사이에서
  보간한다. 일반 timer와 FINAL/LAST window timer를 동시에 겹쳐 표시하지 않는다.
- spectator panel은 서버가 `LAST_ATTEMPT_WINDOW`, viewer 2 Clears, opponent 1 Clear를 모두
  확인해 `spectator.active=true`를 반환할 때만 보인다. 기존 양쪽 Score/Clear HUD는 유지한다.
- 클라이언트 progress는 정수 % 변경 시 후보로 만들고 최대 10Hz로 전송한다. 서버도 10Hz로
  제한해 `MatchRuntimeStatePort`의 in-memory active-attempt 상태만 갱신한다. PostgreSQL에는
  progress row를 만들지 않으며 score/clear/winner 계산에는 사용하지 않는다.
- 2-Clear viewer의 추가 attempt는 UI에서 막고, 우회 요청도 rules engine이
  `LAST_ATTEMPT_TARGET_ONLY`로 거절한다.

## Debug Bot Match

- 클라이언트 진입은 compile-time `CORUM_RANKED_DEBUG_BOT_MATCH`; 서버 생성은 runtime
  `ENABLE_DEBUG_BOT_MATCH`와 request body의 password 검증을 모두 통과해야 한다.
- Bot은 Queue에 들어가지 않는 server-side event generator다. Ready, ban, attempt
  start/progress/end/clear를 일반 `MatchService`와 rules engine에 넣는다.
- 난이도별 MMR offset, Qualifying 도달 확률, Clear 확률, 진행 속도와 tick/delay는 전부
  환경변수로 조정한다. Clear 확률은 Qualifying 도달 확률을 넘을 수 없다.
- scenario는 Normal, Force Bot 1/2 Clears, LAST ATTEMPT, Round Draw, Round 3,
  Deathmatch를 지원한다. LAST ATTEMPT는 실제 spectator state와 overlay를 사용한다.
- `match_type=DEBUG_BOT`와 debug config로 식별하지만 rating 적용을 건너뛰지 않는다.
  일반 `calculateMmrUpdate`와 같은 profile transaction이 player MMR, visible Ranked Score,
  Placement, W/L, displayed tier와 match history를 갱신한다.
- Discord event는 생성 화면 기본 OFF이며 match 단위 DB flag가 outbox 생성을 차단한다.
- release에서는 서버 flag를 false로 하고 password를 제거한 뒤 Geode를
  `-DCORUM_RANKED_DEBUG_BOT_MATCH=OFF`로 빌드한다. OFF Android64 binary에서 debug popup,
  label, password error, scenario와 route 문자열이 없음을 확인했다.

## 맵 ID와 sheet1

- `setupCorumRankedConfig()`은 기존 맵 시트(`sheet1` 또는 `MAPS_SHEET_NAME`) 오른쪽에
  `Ranked Pool (1~6)`과 `Qualifying %`만 추가한다. 별도 `Ranked Pool` 탭은 만들거나 읽지
  않는다.
- canonical identity는 기존 `맵 코드`, alternate는 같은 행의 `대체 맵 코드`다. 유효한
  alternate가 있으면 모든 PvP/Bot/Bo3/Deathmatch가 이를 playable로 사용하고, 없을 때만
  canonical로 fallback한다.
- candidate 중복과 운영 데이터 연결은 canonical 기준이다. canonical/alternate alias가
  다른 맵과 충돌하면 queue config가 fail-closed된다.
- Match/Round snapshot은 canonical, alternate, playable, 제목, 제작자, 난이도, Pool,
  Qualifying을 저장한다. 이후 Spreadsheet 변경은 진행 중 Match를 바꾸지 않는다.
- 모든 attempt는 client가 보낸 Level ID와 snapshot playable ID가 같아야 승인된다.
